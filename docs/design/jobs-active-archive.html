Active jobs & Archive

TL;DR. Keep one jobs table; status decides where a job shows up. /jobs gets two tabs: Active (active + on hold) and Archive (complete). Office and admin change status from the job page; archived jobs become read-only.
  • Prototype: try it below. Switch role and card style; mark a job complete and watch it move to Archive.
  • Comparisons: navigation pattern, card density, status badges.
  • Idea bank: mark each idea v1 / later / drop, add notes, then Copy as markdown and paste it back to Claude.

2 · Where does Archive live?

Three navigation patterns. They all use the same database query; only the URL and screen layout differ.

Tabs on /jobs Recommended

  • One place to look; the counts show the archive exists
  • A ?view=archive link can be shared
  • Matches shadcn Tabs, which is already in the UI kit
  • Search and filters only appear on one tab, so the tab content varies

Separate /jobs/archive route

Jobs list … View archive (6) → at the bottom
  • Keeps the Active screen simple
  • Archive can grow its own layout, e.g. a table on desktop
  • Easy to miss on mobile
  • Adds a route, which means updating the codebase map

Status filter chips

Active On hold Complete All
  • Flexible; office staff can view "All"
  • "Archive" isn't named as a place, so it's a weaker mental model for field crews
  • Mixing statuses makes the list noisy
